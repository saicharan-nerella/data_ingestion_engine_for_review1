# Data Ingestion Engine

A fully pluggable data pipeline framework. Every layer is swappable:
architecture pattern, readers, writers, orchestrator, alerts, and logger —
all chosen via a single config file (or the UI).

## Quick start

```bash
pip install -r requirements.txt
cp .env.example .env          # fill credentials
# Edit config/config.yaml OR use the Pipeline Builder UI
python -m core.runner
```

## Architecture patterns

| Pattern     | Best for                               | Latency |
|-------------|----------------------------------------|---------|
| Medallion   | Lakehouse (Bronze → Silver → Gold)     | Batch   |
| Lambda      | Batch accuracy + real-time speed       | Mixed   |
| Kappa       | Stream-only, replay via Kafka          | Low     |
| Data Vault  | Regulated industry, full audit trail   | Batch   |
| Data Mesh   | Large orgs, federated domain ownership | Mixed   |

## How pluggability works

```
UI  →  pipeline_config.yaml  →  core/pipeline_builder.py  →  core/registry.py
                                        ↓ importlib.import_module
                            [ArchitectureClass, ReaderClasses, WriterClasses,
                             OrchestratorClass, AlertClasses, LoggerClass]
```

**To add a new component:**
1. Create the file in the correct layer folder
2. Implement the base class contract (`BaseReader`, `BaseWriter`, etc.)
3. Register it in `core/registry.py`
4. It immediately appears in the UI and is selectable in config

## Folder structure

```
data_ingestion_engine/
├── core/
│   ├── registry.py          ← maps names → class paths
│   ├── pipeline_builder.py  ← resolves + wires all components
│   └── runner.py            ← entrypoint
├── config/
│   ├── pipeline_config.yaml ← generated by UI or edited manually
│   └── secrets.yaml         ← git-ignored credentials
├── architecture/            ← 5 swappable patterns
├── ingestion/               ← 7 swappable source connectors
├── target/                  ← 5 swappable sink connectors
├── orchestration/           ← 4 swappable schedulers
├── alerts/                  ← 4 swappable alert channels
└── logger/                  ← 4 swappable log backends
```
